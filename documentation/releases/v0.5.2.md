# v0.5.2 — Compatibility and reliability fixes

This prerelease adapts selected fixes from Hugo Leij's fork to the existing
79thales architecture. It adds capability-selected native temperature members
for Home Assistant 2026.11, prevents account replacement during duplicate setup
and reauthentication, removes raw personal API data from debug logs and safely
suppresses incomplete or ambiguous producer records. Existing identifiers,
manual OFF, clock programs, timed overrides and export safeguards are retained.

The bundled anonymous English dashboard templates and offline generator retain
the control-first layout, temporary-temperature controls, detail views, current
power and calendar energy in kWh. Prices, cost calculations and price bindings
are excluded. Generating a dashboard does not control heating or remove custom
Home Assistant configuration automatically.

No holiday-restoration automation, energy-history backfill or producer-ID
migration is introduced. The export overlay remains experimental. Both native
and legacy temperature-interface contracts are tested; the complete CI runtime
matrix covers Home Assistant 2026.10.1 and 2026.10.4. Full Home Assistant 2026.11
runtime testing remains a separate verification step.

See [comparison](../../docs/HUGO_FORK_COMPARISON.md) and
[integration and test report](../../docs/HUGO_INTEGRATION_REPORT.md) for source
commits, design decisions and verification limits.

Install `remeha_home.zip` through HACS or extract it into
`custom_components/remeha_home`. Restart Home Assistant after installation to
load the Python changes. Publishing this release does not install it or restart
an existing instance.
